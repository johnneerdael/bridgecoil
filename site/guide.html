Get the app

The release workflow produces a signed Android arm64 APK for your phone, plus a SHA256SUMS file. Visit GitHub Releases to see which builds are available and read their individual notes.

Connect your TV

  1. Use the same local network. Connect your phone and TV to the same network. Enable Wi-Fi on the TV; Wireless debugging can turn itself off on a wired-only connection.
  2. Unlock Developer options. On the TV, open Settings → System → About and repeatedly select Android TV OS build. Exact names and placement vary by firmware.
  3. Enable Wireless debugging. Open Developer options, turn it on and allow the current network if the TV asks. Open the option to pair a device with a code.
  4. Pair in Bridgecoil. Select the discovered TV, or enter its address and pairing port when needed, then enter the pairing code shown on the TV.
  5. Connect and check the target. Pairing establishes trust; the connection uses its own endpoint. Confirm the selected device and profile before changing anything.

If pairing expires, open a new code on the TV. If local-network access is denied on the controller, allow it in system settings. A pairing failure and a permission denial are different from an offline TV.

A TV without the required debugging option may need a different setup method. Do not assume every firmware supports phone-only first connection.

Keep the apps you want

Open Apps to browse installed packages. Inspect the friendly name, package ID and selected profile before acting. Community ratings from Universal Android Debloater provide context; they do not prove that a package is safe to disable on your TV.

  1. Select the apps you want to change and read their descriptions.
  2. Review the exact action and the target device/profile.
  3. Apply it, then read the result for each package. A partial result means some packages changed and others did not.
  4. Use Enable to restore a disabled package when the device supports it.

Disabling a package differs from removing it for a profile or uninstalling it. Reinstalling a package does not restore deleted app data. Unrated packages remain unknown.

Choose your Home screen

Keep the stock launcher available while trying a replacement. Choose the new launcher, make it Home and press Home on the physical remote to check where the TV actually goes.

Only disable the old launcher after that check passes. Keep the recovery action accessible, and check Home, Back and D-pad navigation again. Manufacturer behavior differs; a successful request alone does not establish that the replacement is working.

Put your remote to work

Use the on-screen remote for navigation and supported media controls. App shortcuts open launchable installed apps. The current TV and connection stay relevant to every action.

Learn and map a physical button

  1. Open button learning and start listening.
  2. Press the button on the real remote. Check the captured event; not every vendor key is accessible.
  3. Choose an app or another key as its action. Tap and hold options depend on the available mechanism.
  4. Prepare the TV toolkit when prompted, then test the actual physical button.
  5. Check operation without the phone and after a TV restart separately. Treat an untested restart as pending.

The original action may run first. The current non-root listener cannot universally suppress it. Power, voice and some manufacturer buttons cannot be captured. Check conflicts before relying on a mapping.

Prepare the TV toolkit

Persistent mappings use tools on the TV. Basic app management and ordinary remote controls do not require the full mapping toolkit.

  1. Choose Shizuku-Next or Porter. Bridgecoil downloads the release, checks its expected signing certificate and installs it.
  2. Start the helper over the current connection.
  3. Install Termux and Termux:Boot through the same guided process.
  4. Connect Termux to the helper. Approve the permission prompt on the TV.
  5. Enable the helper’s start-at-boot setting. Bridgecoil prepares a startup script and checks the setup’s result.

The helper supplies an execution path; the TV-side listener handles button events. Installing the helper alone is not proof that a mapping works or survives reboot.

When setup needs attention

Play Protect may block the Termux apps because of their older Android target. Read the TV’s prompt and decide there whether to continue. Bridgecoil does not turn Play Protect off.

Shizuku-Next cannot replace another app occupying the same package name when the signer differs. Porter can be installed alongside it. Some TVs restrict Termux access or prevent automatic helper startup; follow the specific result instead of assuming persistence.

Go deeper when you need to

Files: browse TV storage, upload, save to your phone, rename, move and delete. Confirm the target path and any data loss before changing files.

Capture: save screenshots and short recordings. Protected streaming surfaces usually appear black; that is a capture restriction.

Diagnostics: inspect filtered logs and run explained advanced commands. Review the exact command and expected effect. Save commands you use repeatedly.

Capabilities vary with Android version, firmware, profile and access. An unavailable capability should be understood before attempting a workaround.

Read the result. Keep a way back.

History records operations for the device. Keep requested, running, verified, rejected, skipped and uncertain outcomes distinct. Sending a request does not prove that the device changed.

If the connection drops during a change, reconnect and inspect the current state before retrying. For batch jobs, read the individual package results. Recovery appears where a real inverse exists; deleted files and app data do not become recoverable just because the operation is recorded.

Compatibility & limits

  • Physical-TV validation is pending. Guided setup has run end to end on an Android TV 16 emulator with secure ADB and no root. That does not establish support for every physical TV.
  • Wi-Fi matters. Wired-only networking may stop Wireless debugging or helper startup. After restarting the TV, start the helper again from Bridgecoil if necessary.
  • Connections have a lifecycle. Android shows a connection service while connected. On iPhone and iPad, returning from another app may require reconnecting.
  • Some keys remain unavailable. Power, voice and manufacturer-specific buttons may be outside the accessible input path; mapped actions can follow the original action.
  • Persistence is device-specific. Some TVs block the access Termux needs. A mapping that works now may still need a separate restart check.
  • Ratings are guidance. Community package ratings are not a guarantee for your TV. Changes affect the selected device/profile.
  • Protected video stays protected. Streaming apps may produce black captures.

Something didn’t work?

Check the selected TV, profile, connection and operation result first. For setup problems, include which step stopped, your TV model, Android version and the Bridgecoil build.

When sharing logs, remove pairing codes, device addresses and other details you do not want public. Do not upload private keys or signing material.
