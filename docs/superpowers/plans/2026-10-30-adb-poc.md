# ADB Connection and Install POC Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for native execution.

**Goal:** Deliver an early Tauri 2 POC for direct ADB pairing, connection and native-picker APK installation, retaining Android and iOS support.
**Architecture:** Rust direct libadb transport with a Svelte/TypeScript interface; stream selected native files through Rust and verify installation using APK package/version metadata.
**Spec:** `docs/superpowers/specs/2026-10-30-adb-workspace-design.md`.

## User priority and rulings

The user approved implementation and explicitly requested connection, pairing and install first for an early POC. Prioritize the applicable parts of full-plan Tasks 1–3 and 8. Defer the broad toolkit without removing it from the product goal. Native execution follows the previously recommended method, avoiding another approval round. Implement useful features while documenting physical-device or signing constraints; do not claim unperformed Android/iOS validation.

## Task 1: Direct Rust core

- [ ] Create failing endpoint, pairing-code, install-result, shell-injection, identity-roundtrip and stale-session tests.
- [ ] Implement app-scoped RSA identity, separate pair/connect endpoints, direct TLS and legacy sessions, device identification, session tokens, streamed sync upload, safe APK installation and post-install verification.
- [ ] Use exact-pinned libadb 0.7.0 with documented TLS trust semantics. Read APK manifest metadata to identify the installed target. Reject incompatible/invalid selections and avoid automatic uninstall/retry.
- [ ] Verify with `cargo test -p adb-core` and `cargo clippy -p adb-core --all-targets -- -D warnings`; add independent protocol/device evidence where available.

## Task 2: Native Tauri POC

- [ ] Write failing frontend state/command tests for pair vs connect, failures, file selection, target change, install review/progress/unknown outcome and duplicate-submit prevention.
- [ ] Build the approved light workspace focused on Connect and Install. Use real Tauri commands; browser preview explains native-only functionality instead of simulating a connected TV.
- [ ] Use native picker/content-URI handling on Android, iOS and desktop. Keep host identity private and persistent; no desktop ADB server dependency. Include local-network platform declarations.
- [ ] Verify frontend checks/tests/build, Rust integration, desktop launch and Android/iOS build configurations. Preserve actual errors and compatibility limits.

## Task 3: Validate and deliver

- [ ] Exercise real rendered flows and independent backend tests. Inspect available authorized test devices without altering existing TV packages or reusing private ADB keys silently.
- [ ] Build installable artifacts where toolchains/signing permit; distinguish native build, emulator, physical-device and untested evidence.
- [ ] Document run/build commands, known limitations and the exact POC boundary. Perform a fresh independent code review, fix significant findings and rerun appropriate checks.
- [ ] Commit on the feature branch, integrate locally after checks and retain recoverable work. No remote, publish or release.
